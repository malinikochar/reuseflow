# Case alignment skill

## Mission
Make this product directly solve the **specific assigned challenge**, not just a generic electronics-refurbishment concern. The public partner description does not establish the contents of the actual case.

## Checklist
1. Read `ReuseFlow_PRD.md` sections 0–3, 10, 16 and `docs/CASE_ALIGNMENT.md`.
2. Ask whether an eligible participant has read the official case and rubric. If not, label alignment `UNVERIFIED`. Never claim the case has been evaluated.
3. Never distribute restricted case text; request only the participant's permitted brief paraphrase and references to sections.
4. Write an evidence table with `Claim | Source | Verified/Assumed` and a clear real-world business KPI.
5. Trace `case problem -> root cause -> primary user -> feature -> KPI -> feasible pilot`.
6. Compare against cheaper alternatives: spreadsheet, simpler operational process, and full app.
7. If the stated case is unrelated to device triage, flag **STOP: CASE MISFIT** and propose a smaller case-specific pivot.
8. Validate every presentation/Devpost claim. Replace unsupported figures with labeled scenarios.

## Deliverable
Complete `docs/CASE_ALIGNMENT.md` with a non-confidential problem summary, evidence register, case-fit verdict (`GO/PIVOT/STOP`) and assumptions. Never upload the case packet to GitHub.
